# product-requirements.md — プロダクト要求定義書

## プロダクトビジョン

Instagram アカウントのパフォーマンスデータを自動取得し、ローカル CSV に蓄積することで、長期的なエンゲージメント推移の分析を可能にする。

## ターゲットユーザー

Instagram アカウントを個人で運用するクリエイター・事業者。  
Meta の提供するインサイト画面では長期データの保持・比較が難しいため、自前でデータを蓄積したいユーザー。

## 解決する課題

- Instagram のインサイト画面は過去データが一定期間で失われる
- 投稿ごとのエンゲージメント推移（公開直後 → 数日後 → 1週間後）を追跡できない
- 複数投稿のデータを横断的に比較する手段がない

## 主要機能

| 機能 | 説明 |
|---|---|
| メディアデータ取得 | 全投稿（画像・動画・リール）の基本情報とインサイトを取得 |
| ストーリーデータ取得 | アクティブなストーリーズの基本情報とインサイトを取得 |
| アカウントデータ取得 | フォロワー数・リーチなどのアカウント全体指標を取得 |
| CSV 出力 | 取得データをローカル CSV ファイルに保存 |
| フェーズスナップショット | 投稿経過時間に応じた間隔でエンゲージメント指標を記録 |
| ハッシュタグ抽出 | キャプションからハッシュタグを自動抽出して保存 |

## ユーザーストーリー

- ユーザーとして、`make run` を実行するだけで最新の Instagram データを CSV に保存したい
- ユーザーとして、投稿公開後の早い段階から定期的に指標が記録されることで、バズの初動を捉えたい
- ユーザーとして、古い投稿は週1回程度の記録でよく、新しい投稿は細かく記録してほしい

## 受け入れ条件

- `make run` 実行で以下4つの CSV が生成・更新される
  - `data/media.csv` — 全投稿の最新スナップショット（毎回上書き）
  - `data/media_snapshots.csv` — 投稿ごとのエンゲージメント時系列（追記）
  - `data/stories.csv` — アクティブなストーリーズ（毎回上書き）
  - `data/account_snapshots.csv` — アカウント指標の時系列（追記）
- フェーズ判定により、必要なタイミングのみスナップショットが記録される
- API エラー発生時にリトライ・ログ出力が機能し、処理が継続される

## 機能要件

- Instagram Graph API v25.0 を使用する
- アクセストークンは設定ファイル（`config.ini`）で管理し、コードに埋め込まない
- ページング対応により、全投稿を漏れなく取得する
- FEED 投稿と REELS 投稿で取得するインサイト指標が異なる

## 非機能要件

- API 接続エラー時は最大3回リトライする（待機10秒）
- すべての処理はログファイルに記録される
- テストは Docker コンテナ内で実行可能であること（`make test`）
