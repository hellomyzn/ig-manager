# requirements.md — Instagram データ取得・管理機能

## 変更・追加する機能の説明

Instagram Graph API を使用して、プログラム実行のたびに投稿・ストーリーズ・アカウントのデータを取得し、Google Spreadsheet に記録する。
GitHub Actions により自動実行し、投稿直後の初速データも逃さず記録する。

---

## 取得対象データ

### A. 投稿（Media）データ

対象：通常ポスト・カルーセル（複数枚）・リール すべて

**基本項目**
| フィールド | 説明 |
|---|---|
| id | 投稿ID |
| timestamp | 投稿日時 |
| caption | キャプション |
| media_type | IMAGE / VIDEO / CAROUSEL_ALBUM |
| media_product_type | FEED / REELS |
| permalink | 投稿URL |
| media_url | 画像・動画リンク |
| thumbnail_url | リール用サムネイル |

**基本数値**
| フィールド | 説明 |
|---|---|
| like_count | いいね数 |
| comments_count | コメント数 |
| is_comment_enabled | コメント許可フラグ |

**インサイト（最重要）**
| フィールド | 説明 | 対象 |
|---|---|---|
| reach | リーチ数 | 全種別 |
| impressions | インプレッション数 | 全種別 |
| saved | 保存数 | 全種別 |
| shares | シェア数 | 全種別 |
| profile_visits | プロフィール訪問数 | 全種別 |
| follows | 新規フォロー獲得数 | 全種別 |
| total_interactions | インタラクション総数 | 全種別 |
| plays | 再生数 | リール専用 |
| video_views | 3秒以上の再生数 | リール専用 |

**分析用（プログラムで生成）**
| フィールド | 説明 |
|---|---|
| hashtags | キャプションから自動抽出したハッシュタグ一覧 |
| fetched_at | データ取得日時（初速分析用に記録） |

---

### B. ストーリーズ（Stories）データ

対象：24時間以内のアクティブなもののみ（API制約）

**基本項目**
| フィールド | 説明 |
|---|---|
| id | ストーリーID |
| timestamp | 投稿日時 |
| media_url | メディアURL |
| permalink | ストーリーURL |

**インサイト**
| フィールド | 説明 |
|---|---|
| reach | リーチ数 |
| impressions | インプレッション数 |
| replies | 返信数 |
| taps_forward | 次へタップ数 |
| taps_back | 戻るタップ数 |
| exits | 離脱数 |

---

### C. アカウント（User）データ

対象：自分のアカウント全体の状態

**基本項目**
| フィールド | 説明 |
|---|---|
| username | ユーザー名 |
| biography | プロフィール文 |
| followers_count | フォロワー数 |
| follows_count | フォロー数 |
| media_count | 投稿数 |

**インサイト（日次データ）**
| フィールド | 説明 |
|---|---|
| impressions | アカウント全体の露出 |
| reach | アカウント全体のリーチ |
| profile_views | プロフィール閲覧数 |
| website_clicks | リンククリック数 |

## アウトプット

- **ローカル CSV ファイル**に保存する
- ファイル構成：
  - `data/media.csv` — 投稿データ（実行のたびに全件上書き）
  - `data/media_snapshots.csv` — 初速データ（投稿ID × 取得日時 の時系列スナップショット、追記）
  - `data/stories.csv` — ストーリーズデータ（実行のたびに全件上書き）
  - `data/account_snapshots.csv` — アカウント日次データ（追記）

---

## 初速分析

投稿直後の数値の伸びを記録するため、**取得日時（fetched_at）を付けて時系列で蓄積**する。
同一投稿IDのデータを複数回記録し、スプレッドシート上で時系列比較できるようにする。

**フェーズ別更新ロジック（GitHub Actions 実行頻度に対応）**

| フェーズ | 条件 | 実行頻度 |
|---|---|---|
| 初速 | 投稿から1時間以内 | 15分おき |
| 初日 | 投稿から24時間以内 | 1時間おき |
| 初週 | 投稿から1週間以内 | 1日1回 |
| 安定期 | 1週間以降 | 1週間に1回 |

---

## 運用スケジュール（GitHub Actions）

- 推奨投稿時間: 21:00 (JST)
- **21:00〜03:00 (JST)**: 15〜30分おき（初速を逃さない）
- **03:00〜21:00 (JST)**: 3時間おき（リソース節約）
- インフラ: GitHub Actions（Private リポジトリ無料枠 2,000分/月 以内に収める）

---

## ユーザーストーリー

- 管理者として、プログラムを実行するたびに最新のInstagramデータを取得したい
- 投稿直後の初速データ（いいね数・リーチ・保存数）を時系列で追いたい
- キャプションから自動でハッシュタグを抽出・記録し、ハッシュタグ別の効果を把握したい
- すべてのデータをローカル CSV で一元管理したい

## 受け入れ条件

1. Instagram Graph API にアクセストークンで認証できる
2. 全投稿の基本情報＋インサイトを一括取得できる
3. リールの場合は専用インサイト（plays, video_views）も取得できる
4. アクティブなストーリーズの基本情報＋インサイトを取得できる
5. アカウント基本情報＋日次インサイトを取得できる
6. キャプションからハッシュタグを正規表現で自動抽出し保存できる
7. 取得日時（fetched_at）を付けて初速データをスプレッドシートに追記できる
8. 取得データをローカル CSV ファイルに正しく書き込める
9. APIエラー時はリトライ処理が働く（既存の `common/request` を利用）
10. 設定値（アクセストークン、ユーザーID）は `config.ini` で管理する

## 制約事項

- Instagram Graph API v21.0 を使用
- ストーリーズは24時間以内のもののみ取得可能（API仕様）
- アクセストークンはページアクセストークン（長期トークン）を前提とする
- 既存の `common/request`、`common/config`、`common/log` モジュールを活用する
- `common/google_spreadsheet` は使用しない
- キャプションの感情分析・詳細テキスト解析はスコープ外
- 可視化ツール（Looker Studio等）はスコープ外、スプレッドシートのみ
- 24時間一律の高頻度実行は行わない（GitHub Actions 制限のため）
